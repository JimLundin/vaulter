# Ticket #24 consumer recheck and retained navigation

Rechecked against the ticket branch before implementation. The approved decisions come from
[#20's agent brief](https://github.com/JimLundin/vaulter/issues/20#issuecomment-6097442566)
and the maintainer reduction inventory; `fe941c2` was only the investigation starting point.

| Design/capability | Rechecked consumer evidence | Planned purpose | Decision and reason |
|---|---|---|---|
| Desktop collapse, icon/offcanvas branches, shortcut and cookie | NavigationSuite mounted the provider with the keyboard listener; only Sidebar catalogue exposed Trigger; Rail and useSidebar had no other callers | No retained collapse purpose | Remove the collapse state/context, public hook/Trigger, private Rail, shortcut interception, cookie write, collapsed width token and all collapsed styling. Keep navigation expanded. |
| Floating/inset Sidebar and right main-navigation placement | No caller selected these options; Product uses the expanded left default | Main navigation left; supporting conversation/evidence right | Remove main Sidebar options and dedicated branches. Supporting panels are independent and unchanged. |
| SidebarProvider and SidebarInset wrappers | Provider wraps NavigationSuite and Sidebar catalogue; Inset supplies catalogue page content | Generic workspace and content layout | Keep wrappers and public presentation; discard provider state and inset-only margins/corners/shadows. Sidebar now occupies its expanded width directly in the flex workspace. |
| Destination outline, top-level alternate sizes, nested small labels, collapse-only tooltips and hover-hidden actions | No current consumer selected alternatives; Product and catalogue use default rows and visible actions | Discoverable navigation and keyboard/current feedback | Remove only rejected props and their styles. Keep plain/default rows and focus/current/hover feedback; keep always-visible actions. |
| Groups/headings/group actions, counts, nested destinations and separators | Paired Sidebar catalogue and browser density checks | Richer future navigation presentation | Keep all public primitives and their touch layout; do not introduce groups/trees into NavigationSuite or change its inputs. |
| Sidebar loading rows and private Skeleton | Sidebar catalogue consumes loading rows; the private Sidebar implementation is Skeleton's only retained source consumer | Hold navigation row space while dynamic destinations load | Keep private Skeleton and public SidebarMenuSkeleton; show both icon and text-only rows. Remove unfinished public Skeleton and its bare zero-height Status example. |
| Phone Menu and navigation overflow | NavigationSuite owns menu state independently; Product and public browser fixtures exercise it | Destinations/actions across compact and expanded arrangements | Preserve existing Drawer, inputs, assembly, dismissal/focus return and resize behavior. |

Shared dependencies: generic Tooltip/TooltipProvider remain available to Product help, chart
readouts and catalogue examples; only Sidebar's collapse-specific tooltip adapter/provider is
removed. The shared button variants, Input, Separator and private Skeleton remain required by
retained primitives. Sidebar colour/touch tokens remain active. No shared package is removed.

Verification uses the user-approved Product/public-kit/browser and policy/coverage seams.
The shortcut regression failed before implementation because Ctrl+B wrote `sidebar_state`;
with the cleanup it passes while preserving destination geometry and the Agent draft.
The root integration run supplies the final full-suite/build record.

24 focused browser cases across phone, desktop and touch desktop. After adding explicit visible
loading text/icon and discoverable-action assertions, the three-project Sidebar catalogue test

5s default under concurrent load; rerun with a command-only 30s timeout passed, with no policy
