DesignComparison accepts a nonempty list of `{ id, label, content }` alternatives and an optional
initial `defaultValue`. Each instance owns selection, shows only the selected alternative and resets
that alternative's content when switching designs. Changing only the device preserves the selected
alternative and its mounted content. Arrow navigation belongs to the focused design radio group;
compact selection uses the native select. Inputs, tabs, radios and other widgets retain their own
keyboard behavior, and unrelated examples never receive comparison shortcuts.

Implementation touches only comparison coordination, its public export, retained-page catalogue
registration and checks. Unlisted and undecided public designs remain available. The common
inventory's earlier observation that comparison was not shared is historical; this record is the
new consumer evidence for that row.

Validation evidence is recorded in the integration result for this ticket. Browser checks cover
pointer/keyboard selection, paired independence, device/draft preservation, controls within bounds
at different outer widths, A/B/C access, and the Product evidence preview through desktop/phone
changes. Full suite and build validation run again on the final integration branch.
