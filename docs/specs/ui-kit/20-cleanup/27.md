# #27: Retire alternative Settings, Search and Dialog shells

Rechecked consumers against the current source before removal. The cleanup follows the maintainer
inventory and approved agent brief; catalogue-only use is evidence, not deletion authority.

| Design or dependency | Rechecked evidence | Decision and reason |
| --- | --- | --- |
| SettingsPage | Settings catalogue and browser field/touch/keyboard fixtures; no Product consumer | Remove the explicitly rejected full-page preferences shell. Preserve interactive field association coverage in SettingsMenu and generic keyboard/touch coverage in FeaturePage. |
| CommandDialog | Search catalogue alternative and public export only | Remove the rejected centered shell and its dedicated command styling. SearchSurface remains the desktop palette/full-screen phone task. |
| Generic public Dialog assembly | Dialog catalogue only; no Product consumer | Remove public Dialog, Content, Title, Description, Header, Trigger and Close exports and their generic example. Modal note review now uses adaptive Overlay. |
| Private Dialog root, content, title, description, portal and backdrop | Overlay and SearchSurface use these adapters, including private presentation-policy scope, modal choice, nested dismissal and focus history | Keep Base UI interaction adapters. Move retained surface framing to AdaptiveDialog; remove orphan header/trigger/default-close branches and their dedicated touch selectors. |
| DialogFooter | Previously demonstrated only by generic Dialog; maintainer explicitly retained its planned confirmation/cancel purpose | Keep public responsive action layout and its existing optional close action. Demonstrate supplied Cancel/Keep actions in adaptive Overlay; desktop actions align right and phone actions stack. No caller styling or mandatory footer. |
| SettingsMenu, SettingsSection, SettingField and ThemeSwitch | Product feature preferences, paired catalogue, field fixtures and browser checks | Keep feature-owned text/radio fields, grouping and theme choices. Paired accessible associations are now checked in retained open Settings drawers. |
| Command and CommandSeparator | Product ranked Search and retained Search catalogue | Keep filtering, caller order, keyboard selection, empty announcements and Product shouldFilter=false behavior under ADR-0001. No changes to the autocomplete implementation. |
| Overlay/Drawer and presentation policy | Product shortcuts/Search/preferences, nested browser tasks and supporting panels | Keep one content tree, bounded portals, nested dismissal and responsive focus restoration. Removing alternative assembly does not redesign their architecture. |

The field fixture opens SettingsMenu through a real button and retains native label activation,
text/radio identities, supplied descriptions, independent repeated controls and focus/state through
resize. The generic navigation fixture uses retained FeaturePage so wide supporting panels can
still verify focus on background content; forcing it into a permanently open modal would invalidate
that test. No meaningful interaction coverage was deleted.

Notifications and navigation consolidation remain follow-up work. Private Base UI dependencies stay;
no package becomes removable through this slice. Unlisted and undecided public designs stay available.
