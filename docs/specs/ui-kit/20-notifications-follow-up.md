## Notification design follow-up

Related cleanup: [#20](https://github.com/JimLundin/vaulter/issues/20).

Published follow-up: [#22](https://github.com/JimLundin/vaulter/issues/22).

The maintainer wants one notification component, with floating presentation above the bottom
navigation on phone and at the lower-right of the content area outside the desktop sidebar.
The notification must retain its content/state when resized and must not shift page content.

Current Product Toaster manages transient messages about saved changes, reverts and unseen Agent
replies. Notice supplies a separately designed attention card with optional title, content and
action; it is not connected to that notification lifecycle. #20 retains both while retiring
the obsolete MobileFrame reserved notice row.

Assess the existing Toaster as the leading shared implementation and how to integrate the retained
attention-card presentation. Agree appearance, lifetime, dismissal and action behavior during the
follow-up rather than assuming a second notification system or every library option is required.

**Established requirements:**

- One shared content/state model with phone/desktop placement, rather than duplicate device features.
- Floating notifications overlay a small part of content; showing/dismissing them does not shrink
  or move the scrolling page.
- Phone placement clears the bottom bar, safe area and any floating primary control, keeping them usable.
- Desktop placement is within the content area, outside main navigation.
- Resize repositions the same notification without duplicate messages or state resets.
- Current saved-change, revert and unseen-reply notifications continue to work.
- Attention requests can present useful content and actions, with accessible announcements,
  keyboard focus and usable touch targets.
- Preview notification content, position and interaction stay within the relevant example.

**Existing preview evidence and unresolved choices:**

The catalogue uses per-example notification IDs and local CSS positioning. Complete focus and
simulated-device isolation is unverified: Toaster does not consume shared presentation policy,
and library sizing/focus behavior can use the real window/document. Review this explicitly.

Lifetime, dismissal affordances, action focus, notification stacking, exact appearance and the
shared component interface still need design decisions. This follow-up starts in needs-triage;
the established placement requirements are not an agent-ready implementation specification.

**Review criteria for the follow-up:**

- Demonstrate existing success/plain messages and an actionable attention request on phone,
  desktop and touch desktop.
- Verify bottom-control/safe-area clearance and desktop sidebar separation.
- Resize a visible actionable notification and verify preserved content/state/focus as appropriate.
- Confirm showing/dismissing notifications does not move page content.
- Verify announcement, keyboard/action/dismissal behavior and minimum touch targets.
- Exercise simultaneous bounded preview examples and confirm content/focus/device isolation.
- Record the agreed design and a concrete implementation brief before changing lifecycle/interface.
