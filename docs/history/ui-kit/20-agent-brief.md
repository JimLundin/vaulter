## Agent Brief

**Category:** enhancement

**Summary:** Remove the UI-kit designs and variations rejected in the maintainer walkthrough,
preserving active behavior and designed support for planned features before navigation consolidation.

**Current behavior:**

The kit contains useful active/planned presentation alongside unwanted alternative shells,
appearances and completed experiments. A maintainer walkthrough has now selected the removal
scope. Current import counts, catalogue-only usage and line-count targets do not define that scope.
The initial investigation used review commit `fe941c2`; recheck consumers at implementation time.

**Desired behavior:**

Implement the following agreed removals together with their obsolete exports, examples, styling
and checks. Retain shared private implementations, tokens and dependencies required by surviving
consumers. Remove an additional private helper only when it is genuinely orphaned by this cleanup
or has no retained consumer or planned capability; this does not authorize additional public-design
removals. Keep anything not explicitly rejected.

Preserve designed maps/charts, wiki/evidence presentation, questions, embedded attributed Panel
content, cards, empty states and supplied visual slots. Keep Notice's attention-card presentation
and existing Toaster notifications. Keep horizontal/vertical dividers, optional alert icons,
information/error alerts, supplementary help tooltips and current typography/layout roles.

Cite/Sources and HoverPreview remain provisionally retained for later feature/input design.
Their open design questions are not deletion authority. Typography/positioning/scrolling behavior
options that were not rejected remain available.

**Key interfaces:**

- The public kit continues to expose retained presentation without className or style.
- NavigationSuite and its Product navigation contract retain the current arrangement during
  cleanup. Richer shared desktop/phone navigation assembly is subsequent work.
- AdaptivePanel/ConversationPanel and Overlay/Drawer preserve one mounted content tree,
  responsive placement, focus restoration, nested dismissal and bounded-preview behavior.
- SettingField preserves accessible labels/descriptions and its exactly-one-supported-text-control
  or radio-group contract. General form fields keep their explicit label associations.
- Command preserves the accepted ADR-0001 Search semantics, including Product-ranked results
  with shouldFilter=false. Private Base UI dependencies remain available to retained surfaces.
- Preview distinguishes device selection from design-variation comparison. Retire rejected
  experiment designs while retaining comparison capability or an agreed shared equivalent;
  do not claim shared variation infrastructure already exists. Do not recreate obsolete input experiments.
- Retained public presentation exports continue to have valid paired catalogue coverage.

**Acceptance criteria:**

- [ ] A durable keep/remove/undecided inventory records consumer evidence, planned purpose and
      reasons for each proposed removal, matching the agreed scope above. Rechecked consumers and
      shared-dependency decisions are recorded.
- [ ] Desktop collapse, shortcut, cookie write and collapse-only presentation disappear; expanded
      desktop navigation and phone Menu behavior pass through the existing navigation interface.
- [ ] Every agreed removal is completed, including obsolete public options/exports, samples,
      dedicated styling, source-unused approved dependencies and obsolete checks. Surviving
      consumers retain shared assets; no extra public design is removed because it is unused.
- [ ] Selected provenance A remains usable on desktop/phone; B/C designs and selectable entries
      are retired without losing future preview design-comparison capability or Product History.
- [ ] Retained planned capabilities remain usable and illustrated. Catalogue examples identify
      Timeline's Today/activity purpose and ListDetail's question/inbox purpose without claiming
      those feature workflows are implemented.
- [ ] Leaflet removal preserves actual MapLibre presentation; visual review confirms retained
      dark-mode map, theme switching, markers/routes and designed sizes.
- [ ] Navigation parity, keyboard use, active states, overflow actions, minimum touch targets,
      focus return, nested dismissal and resize/content preservation pass. Retained adaptive
      supporting content stays mounted and bounded examples stay contained.
- [ ] Paired catalogue examples and public-export coverage pass. Behavior fixtures migrated from
      rejected presentation still check retained interactions; meaningful accessibility checks remain.
- [ ] Typecheck, lint, Vitest, the browser suite across phone/desktop/touch-desktop, and Product
      and design builds pass. Review Product preview and retained catalogue examples; document
      any external map-tile limitation honestly if it prevents complete visual validation.
- [ ] Documentation describes retained scope and provisional/follow-up choices. Existing
      notification behavior survives; notification integration/placement is tracked separately.

**Out of scope:**

- Navigation consolidation and subsequent architecture deepening.
- Shared notification integration, agreed phone/desktop placement, bottom-control clearance and
  notification-specific preview improvements; these belong to the approved separate follow-up
  [#22](https://github.com/JimLundin/vaulter/issues/22).
- Implementing planned inbox, embedded-content evidence connectors, touch/keyboard note previews,
  new chart types, generic loading blocks or richer navigation feature workflows.
- Broader Settings, conversation, typography or layout redesign.
- Purging catalogue-only or currently unimported designs without an explicit removal decision.
